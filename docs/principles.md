# Principles

1. **People and agents pair, and swap roles.** The agent brings speed and breadth; the person brings context, judgment and accountability. Neither works alone. Every so often they swap: the person does the work, the agent reviews. That keeps the person's skills sharp, and teaches the agent the squad's style.
2. **Opportunity, design and acceptance criteria come before code.** An agent is only as good as what it's given. Spend effort here, not fixing the solution after. Break work into the smallest iterations that still ship - that's what makes delivery predictable.
3. **Nothing verifies itself.** Agents produce work fast, so checking has to keep pace. A second model or person always reviews, looking for how it fails, not whether it looks fine. Security and quality are checked throughout the build, not bolted on at the end, backed by regular human-led penetration testing. Checks are automated so they repeat, and security testing stays in scope, against systems you own.
4. **People hold gates, not agents.** Spec approval, design, merge, release - a person decides each one. Agents advise; they don't decide.
5. **A squad owns the solution from inception to production.** A small cross-functional team - product, engineering, platform - owns the opportunity and designs the solution together, in the room. Product brings the customer and the real limits on scale, cost and time; engineering brings what's feasible and what it costs. Together they keep it proportionate. No one designs alone.
6. **Context lives where agents can read it, but humans own it.** Conventions, architecture, standards, business knowledge: if an agent can't read it, it can't use it. Every piece has an owner keeping it current, because stale context produces confident wrong answers.
